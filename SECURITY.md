# Security Policy

## Reporting a vulnerability

Report suspected vulnerabilities privately through `<SECURITY_CONTACT_OR_PRIVATE_CHANNEL>`. Do not create a public issue or disclose secrets, exploit details, or sensitive evidence in public channels.

This repository is not ready for publication while this placeholder remains unresolved or the private channel has not been tested.

## Handling reports

Maintainers should acknowledge private reports, limit access to the report, and coordinate a safe resolution. Sanitise logs, screenshots, and reproductions before sharing them. Protect personal and sensitive data throughout investigation and discussion.

If a secret may have been exposed, revoke or rotate it promptly and review related access. Before publication, review Git history as well as current files for accidental disclosure.

## Public-readiness decision

Record publication readiness, residual risks, and private-channel evidence in the [repository engineering contract](docs/repository-engineering.md). An adopter may choose a private disclosure mechanism after completing bootstrap decisions; this template does not configure one.
