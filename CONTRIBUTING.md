# Contributing

## Start with the work

Significant work should start with an issue that explains the problem and avoids duplicates. Keep changes focused and use any branch model that suits the adopting repository; this template does not prescribe one.

## Prepare a change

- Use Conventional Commits when commits are created.
- Link the related issue in a small, focused pull request.
- Include relevant tests or other validation evidence.
- Follow the adopted [repository engineering contract](docs/repository-engineering.md) for canonical quality and change-governance evidence.
- Update documentation when behavior, decisions, or contributor guidance changes.
- Call out security or privacy impact, including when there is none.

## Review and completion

Request review, address feedback, and keep the pull request understandable without unrelated changes.

A change is done when its issue is linked when applicable, scope is focused, evidence is recorded, documentation is current, security and privacy are considered, and required review is complete.
